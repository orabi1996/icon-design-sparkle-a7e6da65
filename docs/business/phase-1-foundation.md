# المرحلة الأولى: أساس بيزنس الشركة وتوصيل الشاشات

## النتيجة

أُضيفت طبقة تأسيسية لتسجيل الشركة/العميل (tenant) مع عضويات، سجل إصدارات غير قابل للتعديل، أحداث أعمال، وحفظ آمن بتعارض متفائل ومفتاح idempotency. أُضيف أيضًا دليل مركزي لكل الشاشات وتقرير أرصدة سلف يعتمد على السجلات الفعلية بدل بيانات تجريبية.

الكود additive: لا يعيد كتابة الموظفين أو السلف القديمة ولا يربطها تلقائيًا بعميل جديد. اختيار الشركة يحدد سياق الإعدادات الجديدة فقط.

## الملفات الرئيسية

- `supabase/migrations/20260914190000_company_business_foundation.sql`: tenants/memberships/company profiles/versions/events، RLS، view للدليل، وRPC الحفظ.
- `src/lib/business-core.mjs`: تحقق الشركة وحساب السلف بوحدات العملة الصغرى وتصدير CSV آمن.
- `src/lib/company-db.ts` و`src/components/hr/CompanyWorkspace.tsx`: React Query واختيار الشركة وإبطال التخزين بعد الحفظ.
- `src/routes/settings.company.tsx`: نموذج الشركة، سبب التغيير، سجل آخر 50 إصدارًا، ورسائل التعارض.
- `src/lib/screen-catalog.mjs` و`src/components/hr/ScreenDirectory.tsx`: فهرس 96 شاشة مع بحث وCtrl/Cmd+K.
- `src/lib/report-rows.ts` و`src/routes/reports.loans-balance.tsx`: تحميل صفحات كاملة، ربط بالمعرّف، مبالغ بالسنت، وتحذيرات السجلات اليتيمة/السداد الزائد.

## عقد الصلاحيات والبيانات

- مالك/مدير الـtenant فقط يقرأ الملف التفصيلي ويحفظه. viewer يرى إسقاطًا محدودًا لاسم الشركة والدولة.
- كل حفظ يحتاج `p_expected_version` و`p_request_id` وسبب تغيير؛ الإعادة بنفس المفتاح تعيد نفس الإيصال، والنسخة القديمة تُرفض.
- الإصدارات والأحداث immutable؛ لا توجد صلاحيات كتابة مباشرة للجداول الجديدة.
- الحقول النظامية تُحفظ كنصوص دون اختراع نمط قانوني للدولة؛ حزم الدولة/الرواتب منفصلة ومراجعة.

## خطوات التفعيل الآمنة

1. نسخة احتياطية وتطبيق migration على staging فقط.
2. اختبار مستخدمين من tenantين: عزل الدليل، viewer، manager، تعارض نسختين، idempotency، ومنع تعديل history.
3. تشغيل `npm install && npm test && npm run check:types && npm run build` في CI. ملف القفل الحالي يحتاج إعادة توليد بسبب optional packages في Tailwind؛ لذلك يستخدم Workflow تثبيتًا إصلاحيًا مؤقتًا. الاختبارات المضافة تشمل 25 حالة، لكن لم يمكن تشغيل npm أو قاعدة Supabase داخل جلسة الإعداد.
4. بعد QA/Product فقط أضف `VITE_COMPANY_BUSINESS_ENABLED=true` إلى بيئة البناء؛ المفتاح مغلق افتراضيًا.
5. نفّذ UAT على عينة صغيرة ثم النشر التدريجي مع مراقبة الأحداث والأخطاء.

## ما لم يُعتمد بعد

- جداول الموظفين والسلف القديمة ما زالت legacy وغير معزولة tenant-wise؛ التقرير الحالي ليس ترحيلًا ماليًا.
- مسير الرواتب/WPS، الحضور والشفتات، الإجازات والموافقات، نهاية الخدمة، الاستبيانات، الفروع والمستندات تحتاج epics مستقلة وقواعد دولة معتمدة.
- رفع الشعار/الختم، دعوات العضويات، الترجمة الإنجليزية، ودفتر حركات سداد السلف ليست مفعلة.
- لا تعتبر الشاشة أو الرابط دليلًا على صحة قانونية أو محاسبية قبل اختبار واعتماد المصدر.
